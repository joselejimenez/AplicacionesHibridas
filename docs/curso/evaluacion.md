# Evaluación

La evaluación sigue la programación didáctica del departamento (apartado 8, *Horas de Libre Configuración: Desarrollo de Aplicaciones Híbridas*).

## Resultados de aprendizaje

| RA | Descripción | Peso | Unidades |
|---|---|---|---|
| **RA1** | Analiza y diseña aplicaciones híbridas, identificando su arquitectura y valorando las ventajas y limitaciones de las diferentes soluciones disponibles | **20 %** | UD1 |
| **RA2** | Desarrolla aplicaciones híbridas implementando interfaces de usuario, accediendo a funcionalidades nativas de los dispositivos y gestionando datos locales y remotos | **40 %** | UD2, UD3, UD4 |
| **RA3** | Optimiza, prueba y despliega aplicaciones híbridas, empleando herramientas específicas y aplicando técnicas para garantizar la calidad y el rendimiento en diferentes plataformas | **40 %** | UD5 |

!!! danger "Hay que aprobar cada RA"
    Para superar el módulo necesitas **un 5 o más en cada uno de los tres RA**. La nota final es la media ponderada de los RA (20 % + 40 % + 40 %).

## Evaluación inicial

Durante la primera sesión harás un cuestionario en Moodle sobre HTML, CSS, JavaScript, Git y conceptos de móvil. **No cuenta para la nota**: sirve para ajustar el ritmo del curso.

## Recuperación y mejora (11–19 de junio)

- Si no has superado algún RA, harás actividades evaluables y una prueba o proyecto individual solo sobre los RA pendientes.
- Si quieres subir nota, puedes pedir un plan de mejora con supuestos más complejos.
- La asistencia es obligatoria durante este periodo.

## Pérdida de evaluación continua

Con menos del **80 % de asistencia** se pierde el derecho a evaluación continua. En ese caso harás una prueba objetiva de todos los RA y CE durante el periodo de recuperación. La fecha se notifica formalmente (Anexo I).

## Honestidad académica

Copiar código de un compañero o entregar código que no sabes explicar supone un 0 en esa actividad. En caso de duda, el profesor puede pedirte que expliques o modifiques tu entrega en clase.
